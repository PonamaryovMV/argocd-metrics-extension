# Новый UI вкладки Metrics

Статический дашборд в светлой теме. Без кнопок: период фиксирован (первое значение `intervals`, по умолчанию `1h`), данные загружаются один раз при открытии вкладки. Чтобы обновить, вкладку открывают заново.

## Где появляется и что показывает

Расширение добавляет вкладку **Metrics** в карточку ресурса Argo CD для `Deployment`, `Rollout`, `StatefulSet` и `Pod`. Набор графиков берётся из `argocd-metrics-server` по `groupKind` ресурса (`deployment`, `rollout`, `statefulset`, `pod`).

- **Deployment / Rollout / StatefulSet**: сервер подставляет `{{.name}}` = `<имя-ресурса>.*`, поэтому в запросы попадают все поды ресурса. Плитки показывают сумму, графики «по подам» — каждый под отдельно, таблица — все поды.
- **Pod**: `{{.name}}` = `<имя-пода>.*`, поэтому все графики и таблица показывают только этот под.

Статусы подов, ноды, рестарты и возраст берутся из дерева ресурсов Argo CD. Маркеры синков на графиках берутся из `status.history` приложения.

## Раскладка

1. Ряд плиток (`graphType: "stat"`). Если у плитки есть threshold с `key: "limit"`, показывается полоса «% от limit», иначе спарклайн и изменение за период. Плитки с одинаковым `group` рисуются одной ячейкой из двух половинок (так сделано «Насыщение»).
2. Графики: `line`, `area`, `bar` (столбцы складываются по сериям, например 2xx/4xx/5xx). Ширина задаётся `span` в сетке из 12 колонок.
3. Таблица подов: колонки CPU/Память берутся из графиков с `metricName: "pod"`.

## Новые поля конфига (все необязательные)

| Поле | Где | Что делает |
|---|---|---|
| `span` | graph | ширина карточки, 1–12 |
| `goodDirection` | graph (stat) | `up` или `down`: в какую сторону изменение считается хорошим (цвет бейджа) |
| `group` | graph (stat) | объединяет соседние плитки в одну ячейку |
| `showPods` | dashboard | `false` скрывает таблицу подов |

`yAxisUnit` понимает `s` (секунды, выводятся в ms), `ms`, `bytes`, `bytes/s`, `%`, `cores`, `req/s` и любые другие подписи.

## Конфиг

Готовый пример лежит в `app/config.json` и `manifests/configmap.yaml`. Оба файла генерируются из `hack/gen-dashboard-config.py`: правьте запросы там и запускайте

```sh
python3 hack/gen-dashboard-config.py
```

Ресурсные метрики (cAdvisor, kube-state-metrics) используют лейблы `namespace` и `pod`. HTTP-метрики ожидаются в формате OpenTelemetry: `http_server_request_duration_seconds_*` с лейблом `http_response_status_code`. Если у вас под и namespace приходят в других лейблах (например `k8s_pod_name`, `k8s_namespace_name`), поменяйте `SEL` в скрипте.

## Сборка UI

```sh
cd extensions/resource-metrics/resource-metrics-extention/ui
yarn install --frozen-lockfile
yarn build            # → dist/extension.tar
```

Новых npm-зависимостей нет: графики нарисованы на SVG, стили встроены в бандл.

## Изменения в сервере

- В `Graph` и `Dashboard` добавлены поля выше, чтобы сервер не отбрасывал их при отдаче конфига.
- Шаг запроса к Prometheus стал адаптивным: около 240 точек на график, не меньше 15 секунд (раньше всегда 1 минута).
